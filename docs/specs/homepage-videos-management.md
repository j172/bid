# SPEC: 首頁官方影音指定與 RSS 補足

## 1. 背景與目標

首頁「官方社群影音動態」目前直接依賴 YouTube RSS。管理員需要能在後台指定優先顯示的 YouTube 影片，同時保留 RSS 作為內容不足時的補足來源。

本功能的目標是提供可控、可預期且不會重複的首頁影音策展流程：指定影片優先，RSS 僅在指定內容不足時補足，最多顯示 6 部影片。

## 2. 產品規格

### 2.1 指定影片清單

- 後台管理員可以新增、編輯、停用與刪除首頁指定影片。
- 每筆資料包含：標題、YouTube URL、排序、啟用狀態與時間戳。
- 同一個 YouTube `videoId` 在資料庫中只能存在一筆；啟用與停用狀態都禁止重複。
- `videoId` 唯一性由服務層友善驗證，並由資料庫唯一索引作為併發時的最終防線。
- 啟用中的指定影片最多 6 則；停用影片不佔用名額。
- 新增或編輯若會造成第 7 則啟用影片，必須拒絕操作並提示管理員先停用其他影片；不得自動停用既有內容。
- 刪除最後一筆啟用指定影片後，前台恢復完全使用 YouTube RSS。

### 2.2 前台顯示與 RSS 補足

- 先依管理員排序顯示啟用中的指定影片。
- 若指定影片少於 6 部，從 YouTube 官方公開 RSS 依最新順序補足，總數最多 6 部。
- RSS 補入時必須排除已指定的相同 `videoId`，不得在前台產生重複卡片。
- RSS 成功但可用影片不足時，只顯示實際可取得的影片，不混入過時的內建影片補滿數量。
- 若沒有啟用中的指定影片，則顯示最多 6 部 RSS 影片。
- RSS 請求明確設定 5 秒逾時；請求失敗或 RSS 回傳空資料時，使用既有的靜態 fallback 影片。
- RSS 請求失敗時，仍保留可用的指定影片；fallback 只用於補足 RSS 本身無法取得的情況。
- YouTube RSS 與 fallback 來源都必須經過相同的 `videoId` 去重與數量上限處理。

### 2.3 快取

- YouTube／首頁影音 feed 維持現有伺服器端短暫快取策略。
- 新增、編輯、停用或刪除指定影片成功後，必須清除影音 feed 快取，讓前台在下一次讀取時取得最新結果。

## 3. API 與資料庫

- 保留管理員授權檢查：未授權請求不得讀寫指定影片。
- 新增與編輯 API 必須驗證標題、YouTube URL、排序與啟用狀態。
- 新增、編輯、刪除的服務層錯誤應轉成穩定、可顯示給管理員的錯誤訊息。
- 新增 `homepage_videos` 表，並在正式環境啟動時以既有 idempotent schema 流程建立。
- 對 `video_id` 建立唯一索引；若既有環境存在重複資料，不由 migration 自動刪除，應先人工清理再套用索引。

## 4. 測試與驗證

- 服務層測試：新增／編輯驗證、6 則啟用上限、全狀態重複、快取失效與錯誤處理。
- RSS 測試：5 秒逾時、指定影片優先、RSS 補足、跨來源去重、RSS 不足與 fallback。
- API 測試：管理員授權、輸入驗證與服務層錯誤映射。
- 執行 `npm test`、`npm run typecheck`、`npm run lint` 與 `npm run build`。
- 合併後執行部署 workflow，並驗證公開首頁、健康檢查與後台管理頁面。

## 5. 非目標

- 不新增 Facebook／TikTok 自動抓取 API。
- 不自動刪除或自動取代既有指定影片。
- 不以 RSS 影片覆蓋管理員明確指定的內容。
